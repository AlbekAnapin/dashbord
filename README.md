# Дашборд качества данных ОВПО

Статический сайт (только HTML + CSS + JavaScript, без сервера и сборки). Загружаете Excel-срез «Не корректные данные» —
сайт разбирает все листы прямо в браузере и показывает сводный рейтинг, рейтинг по качеству, динамику и карточку каждого ОВПО.
Файлы никуда не отправляются.

## Что внутри

| Вкладка | Что показывает |
|---|---|
| Обзор | KPI, топ-15 проблемных ОВПО, структура ошибок по источникам, распределение баллов, средний балл по показателям, динамика |
| Рейтинг по качеству | Баллы 0–100 по критериям «Корректность / Заполненность / Исполнение», итог, ранги, изменение к выбранному срезу, выгрузка в Excel |
| Сводный рейтинг ошибок | «ОВПО / Общее количество ошибок», % от общего числа, накопленный %, разбивка по источникам, включение/выключение источников, выгрузка в Excel |
| Динамика | Графики по срезам, таблица «ошибки по источникам и срезам», ОВПО с лучшей и худшей динамикой |
| ОВПО | Карточка организации: поиск по названию, баллы, ранги, топ-12 полей с ошибками и **подробная расшифровка по каждому листу**: какие поля не заполнены или заполнены некорректно, сколько ошибок по каждому полю, в разрезе годов, категорий (обучающиеся / отчисленные / выпускники), общежитий и административных отчётов |
| Учитываемые показатели | Дерево «раздел (лист Excel) → таблица → поле (столбец)» с флажками: что не учитывать в расчётах. Исключение действует на все рейтинги, баллы, сводные суммы, динамику, обзор и карточку ОВПО |
| Данные и настройки | Загрузка срезов, список действующих ОВПО, веса критериев, публикация (bundle.js), методика |

## Что учитывать (вкладка «Учитываемые показатели»)

* Снимите флажок у **раздела** (например, «Административные отчёты»), у **таблицы** (например, «ГБД ФЛ — Выпускники») или у **отдельного поля** (например, «Другая фамилия»).
  Для админ. отчётов полем является конкретный отчёт (ВП-1, ВП-2…), для корпусов МТБ — вид объекта, для годов (генерация дипломов, GPA, оцифровка) — конкретный год.
* Рядом с каждым полем показана сумма ошибок по всем ОВПО — удобно решать, что исключать. Есть поиск по названию поля.
* Сверху — сводка: сколько ошибок в расчёте, сколько исключено и сколько показателей рейтинга по качеству осталось.
* Исключённое не попадает в итоги, баллы, ранги, динамику, обзор и сводный рейтинг. В карточке ОВПО оно остаётся видимым, но перечёркнуто и помечено «не учитывается».
* Если исключено поле, итог таблицы считается как сумма оставшихся полей. Если исключены все поля таблицы (или все таблицы листа) — показатель полностью выпадает из рейтинга по качеству, а не считается «нулём».
* Настройка сохраняется в браузере и попадает в `bundle.js`, поэтому сотрудники видят дашборд с теми же исключениями.

## ID записей (вкладка «ОВПО»)

В тех разделах, где в Excel есть столбцы с ID (генерация дипломов, дубли ИИН — `studentid` / `tutorid`, оцифровка, GPA, полнота данных ППС), в карточке ОВПО появляется кнопка
**«Показать ID (N)»**. Откроется панель со списками ID по группам (например, «Дубль в одном вузе» или «Выпуск 2025»): их можно выделить и скопировать,
нажать «Копировать» у группы / «Копировать все ID» или «Скачать CSV» (ОВПО; раздел; таблица; поле; подгруппа; ID — открывается в Excel).

## Детализация по полям (вкладка «ОВПО»)

* **Поиск:** начните вводить название в поле поиска (достаточно части слов, например «казах педаг»), стрелки ↑↓ и Enter — выбор.
* **Разделы по листам:** ГБД ФЛ (обучающиеся, выпускники, ППС — по каждому типу ошибки), ОСМС (категории и поля), Генерация дипломов (по годам),
  Дубли ИИН (в том числе с какими вузами и сколько), Оцифровка (по полям и по годам выпуска), GPA (по степеням и годам выпуска), ППС, МТБ, Госуслуги, Админ. отчёты.
* Для каждого поля: число ошибок, % от итога таблицы, сумма по всем ОВПО и доля данного ОВПО. Можно скрывать поля без ошибок и сортировать по убыванию.
* ОСМС и GPA разделены на категории (ОСМС — обучающиеся / отчисленные / выпускники; GPA — обучающиеся / выпускники) в сводном рейтинге и в карточке ОВПО.
  На баллы рейтинга по качеству разделение не влияет (там остаётся общий итог).
* Подписи некоторых столбцов в исходном Excel обрезаны. Для ГБД ФЛ (обучающиеся) они восстановлены по блоку выпускников, одинаковые названия различаются буквой столбца.
* Срезы, сохранённые прежней версией сайта, не содержат детализации: загрузите исходный файл заново.

## Как открыть и проверить у себя (до публикации)

1. Распакуйте архив.
2. Дважды щёлкните `index.html` (Chrome, Edge, Firefox). Интернет не нужен: библиотека чтения Excel лежит в `assets/`.
3. Перетащите Excel-файл(ы) среза в окно. Можно сразу несколько срезов — тогда заработает динамика.
4. Файл со списком действующих ОВПО (названия в первом столбце, заголовок «ОВПО») тоже можно просто перетащить —
   он распознаётся автоматически. Либо загрузите его на вкладке «Данные и настройки».
5. Вкладка «Данные и настройки» → блок «Проверка разбора» показывает, какие листы найдены и сколько строк прочитано.
   Если структура листа изменилась, там появится предупреждение.

## Публикация на GitHub Pages для сотрудников

1. Создайте репозиторий на GitHub и загрузите в него **содержимое этой папки** (`index.html`, `assets/`, `data/`, `.nojekyll`).
2. Settings → Pages → Source: *Deploy from a branch* → ветка `main`, папка `/ (root)` → Save.
3. Через минуту сайт появится по адресу `https://<аккаунт>.github.io/<репозиторий>/`. Эту ссылку и отправляйте сотрудникам.

### Что и как обновлять (без сервера — через файлы в папке `data/`)

| Что изменилось | Что сделать |
|---|---|
| Новые данные (срезы) | Откройте сайт у себя → загрузите срезы → «Данные и настройки» → **Скачать bundle.js** → замените `data/bundle.js` → commit |
| Только настройки (что учитывать, веса, список ОВПО, исключения) | Откройте сайт с `?edit` → внесите правки → **Скачать settings.js** → замените `data/settings.js` → commit. Данные перезаливать не нужно |

* **Настройки закреплены для всех.** Как только в репозитории есть опубликованные настройки (`data/settings.js` или настройки внутри `bundle.js`), каждый посетитель видит именно их:
  учитываемые показатели, веса, список ОВПО и исключения менять у себя он не может (флажки заблокированы, локальные изменения не применяются).
* **Как править самому:** откройте сайт по адресу с `?edit` в конце (например `index.html?edit` или `https://…github.io/репо/?edit`; для локального файла подойдёт и `index.html#edit`).
  В этом режиме всё редактируется; изменения видны только вам, пока вы не опубликуете файл.
* Если есть и `settings.js`, и настройки в `bundle.js`, применяется **более свежий** по дате публикации.
* Это не защита паролем: любой, кто знает про `?edit`, сможет поправить настройки **у себя на экране**, но другим посетителям это не повлияет.

### ID записей и конфиденциальность
* ID студентов / выпускников / ППС по умолчанию **не попадают** в `bundle.js` (в файле остаются только числа по ОВПО). Чтобы сотрудники тоже видели ID, поставьте галочку
  «включить ID записей в bundle.js» на вкладке «Данные и настройки» перед скачиванием (файл станет заметно больше).
* Сайт на GitHub Pages по умолчанию **доступен всем, у кого есть ссылка**. Если публиковать открыто нельзя, используйте вариант с ограничением доступа
  (корпоративные планы GitHub) или внутренний веб-сервер: сайт — обычная папка со статическими файлами.

## Особенности разбора

* **Дубли ИИН** — поддерживается новый формат (с 23.11): построчный список записей, слева обучающиеся (`studentid`, «Тип дубля», «Причина», «ВУЗы по ИИН»), справа ППС (`tutorid`, «Тип дубля», «Все вузы, где дубль»).
  Считается число записей по типам дубля и по причинам, а список «с какими вузами» строится из столбцов со списками вузов. Прежний формат (сводка по вузам) тоже читается.
* **Оцифровка дипломов** — столбец «Не оцифрованно кол-во дипломов 1991г» считается как обычное поле и входит в сумму (в исходном «Общем количестве ошибок» его нет). Повторяющаяся строка заголовков поддерживается.
* **ОСМС** — поддержаны заголовок в две строки («Назначение (обучающиеся)» / «Подсчёт ошибок») и в одну строку («…Подсчёт ошибок», «ВСЕГО Ошибок»), первый столбец может называться «ОВПО», «ВУЗ» или «Университет».
* **Список действующих ОВПО определяет состав расчёта:** организации из списка, которых нет в файле (например, на листах, где перечислены только вузы с ошибками), считаются ОВПО без ошибок.
* **Лист «МТБ»** в виде реестра общежитий без столбца «Причина» (как в файле от 23.11) не даёт списка ошибок, поэтому показатели МТБ для такого среза не считаются — об этом будет предупреждение.

## Какие листы ожидаются в Excel

ГБД ФЛ · ОСМС · Генерация номеров дипломов · Дублирование записей по ИИН · Оцифровка дипломов · GPA не заполнен ·
Полнота данных ППС · Материально-техническая база · Государственные услуги · Административный отчет.

Колонки ищутся **по названиям заголовков**, а не по номерам, поэтому небольшие изменения порядка столбцов не ломают разбор.
Лист «Государственные услуги» — столбец «Итого (кол-во срок обработки заявки истек)»; формат «Принято / Отклонено» не поддерживается.
Срезы в старом формате (28.10) читаются частично: отсутствующие листы (GPA, админ. отчёты) отмечаются как «нет листов» и не считаются нулём.

## Структура папки

```
index.html            страница
assets/core.js        разбор Excel и расчёт рейтингов (без привязки к интерфейсу)
assets/charts.js      графики на чистом SVG
assets/app.js         интерфейс
assets/style.css      оформление (светлая и тёмная тема)
assets/xlsx.full.min.js   SheetJS 0.18.5 — чтение/запись Excel
data/bundle.js        опубликованные данные (заменяется при обновлении)
```

## Что можно настроить в коде

* Показатели, критерии и список источников сводного рейтинга — массивы `INDICATORS` и `UCOLS` в `assets/core.js`.
* Названия-варианты одного ОВПО (например, «Академия КНБ РК») — `ALIAS_RULES` там же.
* Порог «красной зоны» на обзоре — константа `RED_ZONE` в `assets/app.js`.
